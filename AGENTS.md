# AGENTS.md

This is a [chezmoi](https://www.chezmoi.io/) source directory for personal dotfiles.

## Applying changes

- Targets in `$HOME` are copies, not symlinks, so edits here do nothing until `chezmoi apply` runs.
- Never run `chezmoi apply` yourself if there is a `onepasswordRead` command in the template.
  Edit the source, then tell the user which targets to apply (e.g. `chezmoi apply ~/.zshrc`) if it can't be run in the background.
- A bare `chezmoi apply` fails non-interactively (`could not open a new TTY`) when a target was modified outside chezmoi.
  There are also scripts that run that require `onepasswordRead`, so this wouldn't work.
- New top-level files that aren't dotfiles (docs, scripts) must be added to `.chezmoiignore.tmpl`, or they get deployed into `$HOME`.

## Gotchas

- `~/.claude/settings.json` is generated by `dot_claude/modify_private_settings.json`, a jq merge over the existing file.
  Keys it pins (`permissions.defaultMode`, `autoCompactEnabled`, `statusLine`, the `UserPromptSubmit` hook, `theme`, `tui`, …) must be changed in the script.
  All other keys (`enabledPlugins`, `skillOverrides`, `permissions.allow`) pass through, so edit the target directly.
- `permissions.defaultMode = "manual"` is a deliberate opt-out of auto mode, not an oversight.
- `userChrome.css` is ignored by chezmoi; the Firefox profile symlinks to it directly.
- Machine-specific values come from prompts in `.chezmoi.toml.tmpl` (`.work`, `.op_account`, `.op_account_work`).
- Every `onepasswordRead` call must pass the account as its second argument (`.op_account` or `.op_account_work`).
  chezmoi's `[onepassword]` config has no `account` field, and otherwise `op` inherits whatever `OP_ACCOUNT` the shell exports.
